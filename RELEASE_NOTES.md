## Highlights

Automatic devenv activation through direnv was broken in v4.15.0 and is fixed here. That release installed devenv's direnvrc into `~/.config/direnv/lib` so a project's `.envrc` could be a single `use devenv` line, which turned out not to work: devenv and nix-direnv each define a function called `_nix_direnv_preflight`, and direnv sources its library directory in alphabetical order, so `hm-nix-direnv.sh` quietly replaced `devenv.sh`. `use devenv` then invoked nix-direnv's version, `DEVENV_BIN` was never set, and the shell failed to build — the visible symptom being a project that appeared to load but handed you the system toolchain instead of its own. Projects now use devenv's documented two-line `.envrc`, which is evaluated after the library directory and therefore takes precedence. `devinit` writes both lines, so nothing is asked of a project by hand.

With trusted-users in place, ptrckr has moved off its flake and onto devenv, secrets and all. Its two encrypted API keys still decrypt through agenix-shell on shell entry, now declared as a devenv input rather than a flake input — this was the migration blocked in the previous release, and both keys were confirmed present in the environment rather than merely evaluating without error. One forced change came with it: the project pinned Node 20, which nixpkgs removed after that version reached end-of-life on 30 April 2026, so it now runs Node 22, the smallest supported step up and the same version ismynbncooked uses.
