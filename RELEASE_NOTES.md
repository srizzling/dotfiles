## Highlights

The flake inputs had drifted between twelve and sixteen months out of date, and this release brings all of them current — nixpkgs moves from 25.11 to 26.11, alongside home-manager, nix-darwin, brew-nix and catppuccin. A year of upstream change does not arrive for free, and three things had to be fixed before the configuration would build again. `python310` has been dropped from nixpkgs since going end-of-life, so the package set now asks for `python3`, which follows the current default and will not break the next time a version is retired. Home Manager's vim module has started defining `home.sessionVariables.VISUAL`, which collided with ours, so ours now takes precedence explicitly. Both fixes are verified by a successful build of the darwin system rather than by inspection.

That upgrade also surfaced a set of deprecation warnings, all of which are now gone. Home Manager renamed the git options — `aliases`, `extraConfig`, `userName` and `userEmail` have all moved under `programs.git.settings` — and catppuccin is migrating port enrollment to `autoEnable`, with `enable` becoming a global switch, so that is now set explicitly to preserve current behaviour. These are pure renames: the build produces a byte-identical store path before and after, which is the clearest evidence available that nothing changed but the spelling. Two warnings remain and neither is actionable here, one being the notice about an uncommitted working tree and the other originating inside nixpkgs itself.

Development environments across all projects are now standardised on devenv. The global `CLAUDE.md` states the rule directly: anything under `~/development/personal` or `~/development/work` defines its environment in `devenv.nix` and activates it through direnv, and nothing else — no bare `shell.nix`, no `devbox.json`, no version managers, no Homebrew, and no globally installed toolchain standing in for a project dependency. Projects predating the rule keep their existing flake devShell until their environment is next reworked, rather than being migrated all at once. devenv itself has moved into the managed package set, having previously been installed by hand into the user's Nix profile, where it sat outside the declarative configuration and would simply have been missing on a fresh machine.

Finally, the version bump rules have been opened up. Every commit type except `wip` now bumps at least the patch version, which brings chore, test, ci, style and perf in line with the documentation and refactoring types added in the previous release. The reasoning is that anything committed here reaches a machine the next time it switches, so it is worth a version; dependency updates are covered automatically, since `gdepup` and `gdepdown` record as chore.
