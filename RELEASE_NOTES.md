## Highlights

devenv is now the only way a project defines its development environment, and the configuration has been cleaned up to say so without contradicting itself. devbox has been dropped from the package set and the two devShells have been removed from this repo's own flake, since a repo that tells every project to use devenv should not carry a competing shell definition of its own. The package test that checked for devbox would have started failing the moment it was removed, so that now checks devenv instead.

Activation happens without per-project ceremony. devenv's direnvrc is installed into direnv's library directory, which direnv sources before evaluating any `.envrc`, so a project needs nothing more than the single line `use devenv` rather than repeating devenv's `eval` bootstrap in every repository. It is evaluated at load time rather than frozen into the configuration, so it stays correct across devenv upgrades, and the cost is a deterministic sixty-millisecond print.

Starting a project is now one command. `devinit` scaffolds `devenv.nix`, `devenv.yaml` and the `.envrc` that `devenv init` does not write for you, then runs `direnv allow`. It refuses to run anywhere outside `~/development/personal` and `~/development/work`, refuses to overwrite an existing `devenv.nix`, and warns when a project still carries a competing `flake.nix`, `devbox.json` or `shell.nix` that ought to be migrated and deleted rather than left alongside. The rule and the command are both documented in the generated `~/CLAUDE.md`, so they apply in any project rather than only where someone remembers them.
