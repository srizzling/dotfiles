## Highlights

CachyOS and Hyprland support landed in v4.11.0, but the README never caught up — it still described a macOS-only, Apple-Silicon-only repository, so the one document explaining how to set this up quietly omitted an entire platform. It now covers both targets and how they differ: nix-darwin manages system and user configuration together on macOS, while Linux runs standalone Home Manager over CachyOS with system packages coming from pacman. The commands backed by `darwin-rebuild` — `switch`, `update` and `rollback` — are marked as macOS-only rather than presented as universal, and the tool listing now separates what is shared from what belongs to one platform.

With every machine now running the Nix configuration, the one-time helpers for escaping the old Homebrew and symlink setup have no remaining users, so they have been removed: two migration scripts, a Fish config converter that nothing referenced any more, and a migration guide that could only ever be followed once, along with the README section pointing at them. That is 859 lines gone, recoverable from tag `v4.12.0` should a machine ever need them again.

The release process itself picked up two corrections. Because cog bumps the version only for features, fixes and breaking changes, a range of pure documentation or chore commits was a no-op — but cog reports that on stdout while still exiting successfully, so `make release` sailed past it and announced a release it had neither created nor pushed. It now compares the tag before and after the bump and stops with the reason. Documentation and refactoring have also been promoted to release-worthy in their own right and now bump the patch version, which suits a repository where a README correction is often the whole point of a change; chore, test and CI commits still do not bump. When nothing in the range qualifies, `make release BUMP=patch` forces one.
